Módulo 2.3 Ruta 2 — La arquitectura

🧩 Capacidades: sabe hacer el trabajo

Una frase activa un artefacto. Capabilities es la capa que transforma la intención en ejecución: skills determinísticas, skills asistidas por IA y sub-agents — cada uno en el lugar correcto.

1

La prueba de Capabilities

Un AIOS supera la prueba de Capabilities cuando escribes una frase corta — /audit, /level-up, /onboard — y un workflow de varios pasos se ejecuta solo y produce un artefacto concreto: informe, plan, código, borrador. Sin instrucciones adicionales. Sin microgestión.

🎯 Definición operativa

Capabilities = skills + agentes registrados y listos. No es lo que Claude podría hacer — es lo que él sabe hacer sin pedir ayuda. La diferencia está en que exista un SKILL.md (o archivo de agente) con instrucciones explícitas sobre cuándo y cómo ejecutarlo.

Disparador
Frase corta o /comando que activa la skill
Workflow
Secuencia de pasos definida en el SKILL.md
Artefacto
Resultado concreto: archivo, informe, código
Cero fricción
Sin microgestión durante la ejecución
2

Skills vs. agentes

Son dos tipos de capability con propósitos distintos. Entender la diferencia evita la supercomplejidad: la mayoría de los casos no necesita un agent; una skill bien escrita lo resuelve en segundos, sin costo de modelo.

✓ Skills (.claude/skills/)

  • ✓Archivo SKILL.md con frontmatter + instrucciones
  • ✓Se ejecuta en la sesión principal (contexto compartido)
  • ✓Ideal para tareas secuenciales y deterministas
  • ✓Puede tener 0 llamadas LLM (script puro)
  • ✓Bajo costo, latencia mínima

⚠ Agents (.claude/agents/)

  • →Subasistente con modelo propio (generalmente más económico)
  • →Contexto aislado — no contamina la sesión principal
  • →Ideal para trabajo iterativo con herramientas
  • →Siempre implica llamadas a LLM (mayor costo)
  • →Último recurso: usa primero la skill

💡 Regla de oro

Si la tarea tiene pasos fijos y predecibles → skill. Si necesita razonamiento iterativo con herramientas (leer un archivo, ejecutar un comando, leer el resultado, decidir el siguiente paso) → agent. Si tienes dudas, empieza con una skill y evoluciona solo si es necesario.

3

Las 3 skills incluidas en el kit

El kit AIS-OS viene con tres skills de propósito acotado: cada una resuelve un problema real del ciclo de trabajo con IA. Son un punto de partida, no un límite: puedes construir sobre ellas.

1
/onboard Configuración del Día 1

Inicializa AIOS en un proyecto nuevo: crea la estructura de carpetas, genera el CLAUDE.md con el contexto del proyecto y configura los permisos básicos. Se ejecuta una vez y luego queda listo.

2
/audit Diagnóstico Four-Cs

Audita el estado actual de AIOS: verifica Context, Connections, Capabilities y Cadence. Genera un informe con brechas y próximos pasos priorizados. Ejecútalo cada vez que el sistema se atasque.

3
/level-up Lanza 1 automatización por semana

El motor de crecimiento. Cada ejecución identifica 1 tarea manual repetitiva y la convierte en un artefacto (skill, agent, script). Todo artefacto nace con bike-method-phase: 1 para rastrear la madurez.

4

Anatomía de un SKILL.md

Cada skill es un archivo Markdown con frontmatter YAML en la parte superior y un cuerpo con instrucciones de ejecución. Claude lee el frontmatter para saber cuándo disparar y el cuerpo para saber cómo ejecutar.

📄 .claude/skills/minha-skill/SKILL.md
---
name: minha-skill
description: |
  Quando disparar: descreva o gatilho em linguagem
  natural. O Claude usa isso para decidir se invoca
  esta skill. Seja específico — evite sobreposição
  com outras skills.
---

# Execução

Passo 1: Leia o contexto atual em CLAUDE.md
Passo 2: Execute [ação específica]
Passo 3: Produza o artefato em [formato/path]
Passo 4: Confirme ao usuário com resumo do feito

💡 Consejo: description es el cerebro de la skill

El campo description es lo que Claude lee para decidir si una skill es relevante para el mensaje actual. Cuanto más claro sea el disparador, menor será la posibilidad de confundirla con otras skills. Usa ejemplos de frases que la activen: "Úsalo cuando el usuario pida /onboard o la configuración inicial del proyecto."

5

Determinístico vs. asistido por IA

No todas las skills necesitan IA. El principio Boring-is-Beautiful dice: usa la solución más simple que resuelva el problema. Sube el nivel de complejidad solo cuando el anterior no sea suficiente.

⚙️ Skill determinista

  • ✓Script bash/python — cero llamadas a LLM
  • ✓Resultado 100% predecible y reproducible
  • ✓Costo cero, latencia mínima (<1s)
  • ✓Ideal para: dar formato, mover archivos, generar boilerplate
  • ✓Fácil de probar y depurar

🤖 Skill con asistencia de IA

  • →Instrucción para Claude + 1 llamada a un LLM
  • →Resultado adaptado al contexto actual
  • →Costo de 1 llamada, latencia de segundos
  • →Ideal para: redactar, resumir, analizar, clasificar
  • →Cuando el script no puede razonar por sí solo

🪜 Escalera Boring-is-Beautiful

1 Prompt guardado — CLAUDE.md con una instrucción permanente. Cero código.
2 Skill determinista — Script o secuencia de comandos. Sin IA.
3 Skill con asistencia de IA — Instrucción + 1 llamada LLM. Se adapta al contexto.
4 Subagente — último recurso. Razonamiento iterativo con herramientas.

6

Construir capabilities mediante /level-up

El motor de crecimiento del AIOS es el /level-up. La lógica es simple: 1 run = 1 artefacto nuevo. Con el tiempo, cada artefacto reduce la fricción y aumenta la velocidad.

💡 Cómo construir una skill nueva

Dos caminos: (1) usa la skill-creator de Anthropic — describe lo que quieres y ella genera el SKILL.md; (2) escríbelo a mano siguiendo la anatomía del tema anterior. La segunda opción es más rápida cuando ya sabes lo que quieres.

/level-up → identifica una tarea repetida → genera SKILL.md → guarda en .claude/skills/ → listo para usar

🚲 bike-method-phase

Todo artefacto creado por /level-up nace con el frontmatter bike-method-phase: 1. Esto indica que estás en la fase de bicicleta: funciona, pero todavía requiere atención manual. A medida que madura, la fase sube.

7

Subagentes (.claude/agents/)

Cuando la tarea exige razonamiento iterativo con herramientas —leer archivos, ejecutar comandos, interpretar resultados, decidir el siguiente paso y repetir—, un sub-agent es la herramienta adecuada. La ventaja clave: se ejecuta en su propio contexto, sin saturar la sesión principal.

🤖 Por qué importa el contexto aislado

Cada sub-agent tiene su propia ventana de contexto. Esto significa que las operaciones largas (auditar 50 archivos, iterar sobre una lista de tareas) no consumen el contexto de la sesión principal. El operador puede seguir conversando y dirigiendo mientras el agent trabaja.

Usa una skill cuando:

  • ✓Los pasos son fijos y se conocen antes de ejecutar
  • ✓No necesitas razonar sobre el resultado intermedio
  • ✓La tarea es corta (minutos, no horas)
  • ✓Es deseable compartir el contexto

Usa un agent cuando:

  • →Necesita un loop: leer → ejecutar → decidir → repetir
  • →La tarea es larga y consumiría el contexto principal
  • →El modelo más barato es suficiente para la subtarea
  • →Paralelismo: varios agents simultáneos

💡 Archivo de agent: misma estructura, ubicación diferente

Un archivo de agente sigue la misma anatomía que SKILL.md (frontmatter name + description + cuerpo), pero queda en .claude/agents/. Claude sabe que debe ejecutarlo como subasistente con contexto aislado, no como instrucción en línea.

Ubicación
.claude/agents/ (a diferencia de las skills)
Aislamiento
Contexto propio, sesión limpia
Modelo
Puede usar un modelo más barato
Último recurso
Siempre prueba primero con una skill
