Qué incluye el kit (no lo elimines)

El kit AIS-OS viene con una estructura mínima deliberada. Cada carpeta y archivo tiene una función definida; eliminarlos o cambiarles el nombre rompe los comandos /onboard, /audit e /level-up. Aprende qué es cada pieza antes de tocarla.

Qué agregar a medida que crece

No todas las carpetas tienen que existir el día 1. AIOS crece contigo, pero de forma orgánica, respondiendo a necesidades reales, no a «quizás algún día lo necesite». Estos son los elementos que aparecen naturalmente a medida que el negocio madura:

S1

Semana 1–4 · Kit base, sin añadidos

Usa el kit tal como viene. Deja que AIOS funcione. Observa qué repites y qué genera fricción antes de crear algo nuevo.

M1

Mes 1–2 · Primeras expansiones orgánicas

Si dejaste de copiar el mismo prompt, crea templates/. Si tienes 2+ workstreams activos simultáneamente, crea projects/ con subcarpetas.

Antipatrones: qué NO agregar

La mayoría de los AIOS que se vuelven un desastre no lo hacen por falta de organización, sino por exceso de estructura prematura. Conoce los patrones que contaminan el sistema y le quitan claridad al agente.

✓ Qué AGREGAR

  • ✓ Carpeta que vas a usar 3+ veces/mes — si no tiene frecuencia, se convertirá en un archivo muerto
  • ✓ Archivo con nombre claro y específico — stripe-api.md sí, api-stuff.md no
  • ✓ SOP cuando alguien nuevo necesite volver a ejecutarlo — documenta solo procesos que se repiten con otros
  • ✓ Sub-OS para una vertical genuinamente separada — youtube-os/ solo si tiene un workflow propio distinto

✗ Qué NO AGREGAR

  • ✗ Dump de email/Slack en references/ — el agente intentará leerlo todo; un contexto inflado = respuestas vagas
  • ✗ Carpeta de carpetas sin archivos — una jerarquía profunda sin contenido es pura burocracia
  • ✗ notes/ misc/ tmp/ inbox/ — cementerios de intenciones; todo entra, nada sale
  • ✗ Crear carpetas de antemano "por si hacen falta" — una estructura sin uso engaña al agente sobre lo que existe
  • ✗ Según el CLAUDE.md de la subcarpeta — uno solo en la raíz; varios crean conflictos de autoridad

⚠️ Regla de oro

Duplicar la estructura del decisions/log.md en otro lugar es el error más silencioso: dos fuentes de verdad para las decisiones significan que el agente no sabe en cuál confiar y empiezas a tener un comportamiento inconsistente entre sesiones.

4

Cadencias sugeridas

El AIOS es un sistema vivo. Sin mantenimiento, las decisiones quedan desactualizadas, los archivos se acumulan y el agente empieza a operar con un contexto deteriorado. Las cadencias de abajo mantienen el sistema en buen estado con el mínimo esfuerzo.

📅

Toda decisión → decisions/log.md

Herramienta nueva, cambio de proceso, elección de proveedor. Cuantas más decisiones se registren, mejor entiende el agente el "porqué" detrás de la estructura, no solo el "qué".

🔌

Cada herramienta nueva → connections.md

Agrega la tool de inmediato, no «después». El /audit lee este archivo para saber qué está disponible: un connections.md desactualizado genera sugerencias incorrectas.

🗃️

Limpieza trimestral → archives/

Cada 3 meses, mueve a archives/ cualquier contexto, proyecto o referencia que no hayas usado. No lo borres: archívalo. El historial tiene valor, pero no necesita saturar el contexto activo.

📝

Revisión trimestral del CLAUDE.md

Las instrucciones del agente envejecen. En cada ciclo, revisa si las preferencias, herramientas y procesos descritos aún reflejan cómo trabajas. Un CLAUDE.md desactualizado es peor que no tener ninguno.

🔄

Cuándo volver a ejecutar con alguien → references/sops/

Un SOP solo necesita existir cuando una segunda persona (o tú mismo, después de 6 meses) necesite repetir el proceso sin contexto. Documenta lo suficiente para eso, no más.

⏱️ Consejo práctico: el disparador adecuado

No programes «revisión de AIOS» en el calendario: vincula cada frecuencia a un evento natural. ¿Tomaste una decisión importante? Regístrala de inmediato. ¿Cerraste un trimestre? Archive + revise CLAUDE.md. ¿Contrataste a alguien? Escribe el SOP. Un desencadenante claro hace que no lo olvides.

La regla de los 3 síes

Cada vez que sientas el impulso de crear una nueva carpeta o archivo en AIOS, responde 3 preguntas. La respuesta determina si lo agregas ahora o esperas. Simple, rápida e infalible.

🔢 Las 3 preguntas

1

¿Es algo nuevo a nivel conceptual?

No es solo una variación de lo que ya existe en otro archivo. Necesita un «contenedor» propio para tener sentido.

2

¿Lo usaré 3+ veces el próximo mes?

La frecuencia es el principal indicador de utilidad. Una carpeta que se visita rara vez es ruido: el agente tiene en cuenta toda la estructura al navegar.

3

¿/level-up dirigiría una skill futura hacia aquí?

Si, al automatizar algo nuevo, el agente lo guardaría aquí de forma natural, este es un destino legítimo. Es una buena señal de que la abstracción tiene sentido.

✓ 2+ síes → Agrega ahora

  • ✓Crea la carpeta o el archivo de inmediato
  • ✓Nombra de forma específica (no genérica)
  • ✓Actualiza el CLAUDE.md si es un nuevo destino recurrente
  • ✓Registra la decisión de creación en decisions/log.md

✗ 1 sí (o ninguno) → Espera

  • ✗No crees una estructura prematura
  • ✗Usa la estructura existente, aunque "no sea perfecta"
  • ✗Reevalúa en 30 días: la frecuencia real se hará evidente
  • ✗Si sigue molestándote, el activador se hará evidente por sí solo

Frameworks de ramificación (futuro) + filosofía

El AIS-OS es un kit intencional, no una plataforma con funciones infinitas. Hay frameworks avanzados que se pueden añadir a medida que madura la operación. Y hay una filosofía que los conecta: claridad por encima de exhaustividad.

🌿 Frameworks de branching (agrégalos cuando la operación lo requiera)

Data Retrieval Hierarchy

Define el orden de prioridad para buscar información: contexto activo → references → archives → web. Elimina la ambigüedad cuando hay conflictos entre fuentes.

Integration Ladder

Jerarquía de profundidad de integración: lectura → escritura → automatización → orquestación. Es útil cuando tienes muchas herramientas y necesitas priorizar.

Error Handling Playbook

Protocolos para cuando el agente se bloquea, se equivoca o entra en un loop. Esencial en operaciones de alta frecuencia o críticas.

Model Selection

Criterios para elegir qué modelo usar en cada tarea: equilibrio entre costo, velocidad y capacidad de razonamiento.

Ingeniería de contexto

Técnicas para estructurar el contexto de modo que el agente encuentre lo que necesita sin sobrecargarse. Incluye chunking, resumen activo y pinning.

Seguridad y permisos

Capas de autorización para operaciones sensibles: qué puede hacer el agente sin preguntar, qué requiere confirmación y qué está prohibido.

🏡 La filosofía final

"Tu AIOS debe parecer un negocio pequeño y bien administrado, no el sótano de un acumulador."

Un negocio bien gestionado tiene procesos claros, espacios limpios, decisiones documentadas y sabe exactamente qué tiene. Un sótano de acumulador tiene todo «por si acaso», nada está donde debería y nadie se atreve a mover nada. ¿Cuál de los dos es tu AIOS?

✓ Negocio bien gestionado

  • ✓Estructura mínima y funcional: cada cosa tiene un lugar claro
  • ✓Decisiones registradas — el agente entiende el historial
  • ✓Archivos activos frente a archivados: contexto limpio
  • ✓Crece según la demanda, sin overhead innecesario

✗ Sótano de acumulador

  • ✗Carpetas para todo — ninguna con contenido útil
  • ✗Archivos «por si acaso» que nunca se abren
  • ✗Contexto mezclado con basura — el agente se confunde
  • ✗Crece sin criterio: cada idea se convierte en una carpeta nueva

🌱 Resumen del módulo

✓
La estructura base es intocable — context/, references/, decisions/, archives/, connections.md y CLAUDE.md existen por una razón específica; eliminarlos rompe los comandos
