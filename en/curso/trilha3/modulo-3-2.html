What /audit does

O /audit is a diagnostic skill that scans your AIOS structure and returns a score from 0 to 100. It reads — never writes — every file that makes up the system: manual, memory, skills, agents, MCPs, decisions, and references. The central question is simple: "is the AIOS well-built?"

✓ What /audit does

  • ✓Reads manuals, memory, skills, agents, and MCPs
  • ✓Score each C from 0 to 25 (total 100)
  • ✓List gaps prioritized by leverage
  • ✓Save audits/audit-{data}.md (optional)

✗ What /audit DOESN’T do

  • ✗Doesn’t write any system files (read-only)
  • ✗Doesn’t run skills or agents during the audit
  • ✗Doesn’t evaluate the quality of the automations themselves
  • ✗Doesn’t suggest new automations (that’s /level-up)

2

Structural, not capability

There is a critical distinction that most users confuse the first time: /audit measures whether the AIOS is well built (structure), not whether it can do something new (capability). The question "could you build an automatic daily brief?" is about /level-up, not /audit.

🎯 The Fundamental Division

Structural (/audit)
  • → Does CLAUDE.md exist, and does it have completed sections?
  • → Are all 7 connection domains covered?
  • → Is there at least 1 recurring trigger?
  • → Are at least 3 skills working?
Capability (/level-up)
  • → Should there be a weekly briefing skill?
  • → Do you need an email triage agent?
  • → Is CRM update automation missing?
  • → What is the next highest-impact automation?
💡
Practical tip

If /audit returns gaps like "you could build X," note them and take them to /level-up. The audit is a mirror for structure—not a strategy consultant. Using them in the same session creates scope confusion.

How the 4 Cs are scored

Each C is scored from 0 to 25. The /audit checks specific criteria in each dimension—it’s not subjective. Below are the exact criteria that determine your score.

Scoring criteria — /audit
Context (0–25)
• CLAUDE.md exists and has completed sections +8
• Defined identity/voice +4
• Memory (.claude/memory.md or similar) +5
• References (.claude/references/) +4
• Documented decisions +4
Connections (0–25)
• Coverage of the 7 connection domains +14
• API guides / tool docs +4
• Freshness (last updated < 30 days) +4
• Well-defined read/write balance +3
Capabilities (0–25)
• 3+ active skills (.claude/skills/) +9
• 1+ custom skill (not from the standard kit) +8
• 1+ agent (.claude/agents/) +8
Cadence (0–25)
• Recurring trigger configured +10
• Recent activity (last 7 days) +8
• Workflow templates +7

Stages — score ranges

The total score (0–100) falls into 4 stages. Each stage has a name, a range, and a practical interpretation of the AIOS state. Most new projects fall between 40 and 70—that’s expected progress, not a failure.

Score Stage Name Practical reading
0–39 Stage 0 Foundation AIOS incomplete. Essential pieces are missing. Run /onboard first.
40–69 Stage 1 Built Functional structure. There are still impact gaps. Use /level-up every week.
70–89 Stage 2 Compounding Solid AIOS. Automations feed back into each other. Focus on quality and coverage.
90–100 Stage 3 Autonomous AIOS in full operation. Score 95 is flexible—system with almost no manual friction.

Gaps by leverage

/audit doesn’t list gaps in random order. It uses a leverage formula to prioritize what to address first: leverage = points lost × impact multiplier. The 3 highest-leverage gaps come with a concrete next step.

Leverage formula
leverage = points_lost × multiplier
points_lost = 25 − score_from_C
multiplier → depends on the type of gap:
0 Tier-1 domains (email, calendar, files) → ×4
Shallow CLAUDE.md / no sections → ×3
without custom skills → ×2
everything read-only (no writes) → ×2
without a recurring trigger → ×2

💡
Don’t solve everything at once

The gap list may have 8–12 items. Focus only on the Top-3 in leverage. Fixing the first usually raises the score by 10–15 points and changes the ranking of the others. Re-run /audit after each improvement.

7

Weekly ritual

/audit is the compounding hook of AIOS. The first run establishes the baseline on Day 7. From then on, you run it every week, resolve the Top-1 leverage item, and watch the score climb. This is the cycle that turns a setup into a system.

Weekly audit cycle

Day 7
First run — baseline

Run /audit for the first time. Accept the score without judging it. Save it in audits/audit-semana-1.md. This is ground zero.

Mon
Review the previous week’s Top 1

Open the latest audit.md. What was the Top-1 leverage item? Was it resolved? Note the status before opening a new session.

/audit
Run the /audit

Run the skill. A new score is generated. Compare it with last week's. How much did it increase? A new Top-3 leverage list is identified.

→
Hand off to /level-up

Take the Top-1 leverage point from /audit and move it straight to /level-up. One gap → one automation. Close the loop for the week.

💡
The compounding effect is real

Resolve 1 high-leverage gap per week. In 4 weeks, an AIOS Stage 1 (57 pts) typically reaches Stage 2 (75+ pts). The rising score is evidence that the system is working — not the individual automation.
